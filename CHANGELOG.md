## [Unreleased]

_Planned changes after **0.1.2**._

### Fixed

- **Void rescue vs rope surf:** **last-safe** snap could repeat-teleport you to a **pre-surf** column (e.g. a **tree** or rim by the anchor) while void rescue skipped saving feet during surf — fall → snap back → fall → kick. **Rope surf** start and **cancel / failed finish** now **`clearLastSafeFeet`**; if a snap still lands unsupported, the saved feet tag is **discarded** before **`relocatePlayerFromVoid`** so the loop cannot reuse the bad spot.
- **FTB Quests (WoF):** **Bind the Lantern to Your Egg** optional rows for **dark** and **gilded** breeds used **`tempered_*_phoenix_lantern`**, but **Wings Of Fire V1.0 (NeoForge 1.21.1)** registers **`wings_of_fire:tempered_dark_phoenixlantern`** and **`wings_of_fire:tempered_gilded_phoenixlantern`** (MCreator id: no underscore before `lantern`). Fire / wind / red / nature keep **`…_phoenix_lantern`**.
- **FTB Quests / rope line:** **Ride the Zipline** and **Complete a Rope Link** previously used **checkmark** tasks (manual click only). The mod now grants hidden advancements **`projectisland:progression/rope_surf_complete`** (full surf to the far anchor) and **`projectisland:progression/rope_link_created`** (successful two-anchor link); dev-progression SNBT uses **`advancement`** tasks so completion tracks gameplay.

## [0.1.2] — 2026-05-09

### Added

- **Starter supply chest:** after a successful first **starter-home** teleport, the server can place **one** vanilla loot chest per starter island region (offset from the spawn column). Loot table **`projectisland:chests/starter_supply`** (harpoon gun, elytra, food, seeds, torches, water bucket, stone tools, planks, golden apples, iron nuggets, gunpowder, paper). Toggle **`starterIslandSupplyChestEnabled`** in **`projectisland-common.toml`**. Region keys are stored in **`FloatingIslandSavedData`** (`StarterSupplyChests`) so the chest is not duplicated. Works alongside optional **Lootr** per Lootr’s chest rules.
- **Modpack build guard:** **`verifyDevProgressionFtbQuests`** Gradle task — **`curseforgeModpackZip`** and **`curseforgeServerPackZip`** depend on it so zips are not built if canonical **`examples/dev-progression/ftbquests/`** files (**`quests/data.snbt`**, **`project_island.snbt`**, **`rpg_series.snbt`**) are missing.

### Fixed

- **FTB Quests (dev progression):** **Ride the Zipline** rewards no longer use **`minecraft:wind_charge`** (not in **1.21.1**); they grant **`minecraft:breeze_rod`** and **`minecraft:feather`** instead. Intro quest text mentions the starter supply chest.

### Release / versioning

- **`mod_version`** set to **`0.1.2`** in **`gradle.properties`**; template **`modpack/curseforge/manifest.json`** **`version`** aligned (runtime zips still inject **`project.version`** via **`writeCurseforgeClientManifest`**).

### Fixed

- **Island HUD world billboard + shaders:** **`endBatch`** the entity-translucent panel **before** `Font` draws so glyph passes do not run with a stale entity/shader bind (fixes **black unreadable “block” text** and **purple-tinted** panels with **Embeddium / Iris** stacks). **`islandHudPanelFillOpacity`** default **0** avoids the translucent quad unless explicitly enabled.

- **Xaero: player-created persistent pins:** sync-created HUD mirrors append an invisible ownership suffix so only those rows are cleared/recolored/temp-toggled. Manual waypoints (including any named with **`[Island] `**) stay untouched. Older PI mirrors without the suffix are no longer matched by “clear managed” (HUD sync off / empty payload); remove those manually in Xaero once if needed.

- **Island HUD / Xaero gold after reconnect vs Waystones activation list:** island visit keys were only appended on **right-click** of a waystone tile. Waystones itself keeps a separate **activated** list (teleport menu). On reconnect our packed visits could be empty or incomplete while Waystones still knew your stones → **`[Island]`** pins lost gold / persistence. Each HUD sync now **merges** `WaystonesAPI.getActivatedWaystones` (same dimension) into `FloatingIslandSavedData` via the existing **`markWaystoneHitsForHudSync`** paths. **`markPlayerUsedWaystoneOnIsland`** only calls **`setDirty`** when a key is newly added (avoids rewriting save data every sync).

- **Island HUD → Xaero gold pin vanishes when leaving an island:** merged terrain can make **`islandOwningSurface`** at the **waystone** differ from the grid cell at the **procedural island center** (where HUD/Xaero pins sit). Only the waystone column was stored in **`waystoneVisitedRegionKeys`**, so off-island color sync treated the pin as unvisited → **temporary** / wrong tint. **Waystone use** now records hits for the waystone column, **player feet**, and **surface winners at both regions’ procedural centers**. Multi-beacon (**void navigation**) refresh no longer wipes **`[Island]`** pins whose regions are still in the visit set but outside the scan radius.

- **Island HUD → Xaero gold pins vanished after reconnect:** an **empty** HUD beacon list (open void with **no** islands inside the server scan radius, or transient surface resolution) still carried **`waystoneVisitedRegionKeys`**; the client treated any empty beacon payload like “clear all **`[Island]`** waypoints” and deleted **persistent** pins. Empty **beacons** now clears managed pins only when **`waystoneVisitedRegionKeys`** is also empty (same shape as sync-disabled); otherwise we **only** refresh colors / temporary flags.

- **Client crash opening Xaero waypoints after reconnect / during HUD sync:** Xaero’s **`GuiWaypoints`** list can throw **`IndexOutOfBoundsException`** if the live waypoint set is mutated (add/remove) while that screen is drawing. Island HUD → Xaero apply is **deferred** until the waypoint GUI closes; pending payloads are dropped when the client level unloads so reconnect does not apply stale data.

- **Island HUD → Xaero duplicate pins after travel:** merged terrain can change the server's authoritative island region while an older **`[Island]`** pin stays at the previous region center (different coords-derived grid key). Single-beacon upsert now removes **same-title** stale pins within a **256-block** Chebyshev neighborhood when their region key disagrees with the beacon, so gold/gray stays tied to the correct region without duplicate rows.

- **Island HUD duplicate waystone titles / wrong gold highlight:** **Waystones** relaxed fallback searched up to **~400** blocks horizontally, so one activated waystone often became the nearest named marker for **many** procedural islands → duplicate **`[Island]`** names on different pins. Relaxed search is now capped to **`horizontalRadius + 72`** (max **160** blocks). **IslandHudBeacon** now carries authoritative **`regionX` / `regionZ`**; Xaero highlight and upsert use **`islandRegionGridKey`** from the server plus a **≤96 block** proximity fallback so **`GOLD`** still applies if chunk-derived coords disagree slightly.

- **Island HUD → Xaero waypoint color showed White:** Xaero **`Waypoint#setColor(int)`** passes the int through **`WaypointColor.fromIndex`** (palette slot), **not** **RRGGBB**. Large RGB values clamped to **WHITE**. **`[Island] `** pins now use **`Waypoint#setWaypointColor`** with **`WaypointColor`** enum presets (**`islandHudXaeroWaypointColorDefault`** / **`Hit`**, defaults **DARK_GRAY** / **GOLD**) and the matching **`Waypoint(x,y,z,name,initials, WaypointColor)`** constructor.

- **Island HUD → Xaero void waypoint flood:** **`XaeroIslandWaypointSync`** previously removed and re-added **`[Island] `** waypoints on **every** sync, so open-void **multi-beacon** payloads filled the minimap and world map (matching the old misleading “sync all to Xaero” billboard comment). It now matches **`IslandHudRenderer`**: unless **`islandHudWorldBillboardVoidNavigation`** is **true**, **multi-beacon** updates are **skipped** (last **single-beacon** markers remain); **empty** payload still clears **`[Island] `** managed entries.

- **Island HUD → Xaero single-beacon replaced list:** single-beacon sync used to remove **all** managed **`[Island] `** waypoints and add only the current island, so visiting a new island removed the previous pin. Single-beacon sync now **upserts** by procedural **region grid** (same as **`FloatingIslandLayout`**) so pins **accumulate** across islands; returning updates that island’s pin (e.g. renamed waystone).

- **Island HUD + Waystones:** HUD titles now read from Waystones' **`WaystoneManagerImpl`** registry (per-waystone stream) instead of scanning many chunks for block entities — avoids **stale** procedural titles after activation, cuts server tick cost that could worsen **rubberbanding**, and clears the per-region title cache on **right-click** of a waystone block so updates apply on the next sync. Removed unused common config **`islandHudWaystoneTitleChunkRadius`**. **Bugfix:** **`FloatingIslandLayout.columnContains`** was called with **(wx, y, wz)** instead of **(wx, wz, y)**, so no waystone ever counted as “inside” the island and titles always fell back to **`FloatingIslandDisplayName`**. **Follow-up:** dropped the **`hr + 10`** axis-aligned prefilter (rim / merged-island waystones could still be inside **`columnContains`** but outside that box); **right-click** handler now runs at **LOW** priority (after Waystones updates) and **pushes HUD sync immediately** so titles are not delayed by **`islandHudSyncIntervalTicks`** (default 40). **Further:** prefer **`WaystoneBlockEntityBase#getWaystone()`** when the chunk is loaded (fresher than the manager copy); **ResourceKey** dimension match also compares **`ResourceLocation`**; **relaxed horizontal** fallback when strict **`columnContains`** matches no named waystone; one-time **WARN** if Waystones is present but reflection init fails; **`debugLogging`** emits per-scan **DEBUG** counters when no title is chosen. **Root cause (debug `namedInDimension=0`):** **`RightClickBlock`** could run **before** **`WaystoneBlock#handleActivation`** assigned the generated name; **`resolve`** then cached an **empty** title for **`islandHudWaystoneTitleCacheTicks`**. Fix: **`MinecraftServer#execute`** defers invalidate + HUD sync to the server task queue (after activation); **only successful titles** are cached (misses are never cached); **`waystoneNameToPlain`** flattens **`Component`** beyond **`getString()`** for server-side edge cases.

- **It Takes a Pillage (Continuation) on floating islands:** `takesapillage:pillager_structure` (bastille / pillager camp) runs **`ModStructureUtils.isRelativelyFlat`** before jigsaw assembly; void columns next to island tops exceed **`max_terrain_range`**, so **`findValidGenerationPoint`** was empty and controlled outposts **always fell back to vanilla `minecraft:pillager_outpost`**. Project Island now runs **`JigsawPlacement.addPieces`** for those ids using the mod’s start pools / depth / span and the **same anchored surface projection** as vanilla jigsaw settlements.

- **Controlled villages vs outposts on mod biomes:** `villageKeyForBiome` matched only vanilla `Biomes.*` holders, so snowy **Biomes O’ Plenty** (and similar) islands picked **`village_plains`**, which **jigsaw placement rejects** for those biomes — villages failed while **`minecraft:pillager_outpost`** (and Takes a Pillage structures) still succeeded. Variant selection and settlement strip checks now use **`BiomeTags.HAS_VILLAGE_*`** and **`BiomeTags.HAS_PILLAGER_OUTPOST`** so tagged mod biomes get the correct **`village_snowy`** / **`village_taiga`** / … id.
- **Floating-islands spawn tuning:** `keepChanceFor` again honors **`floatingIslandsSpawnTuningBypassEntityNamespaces`** and **`floatingIslandsNaturalIllagerSpawnKeepChance`** (they were defined in config but not applied).

- **It Takes a Pillage (`takesapillage`):** controlled settlement **outpost** rolls no longer hardcode only **`minecraft:pillager_outpost`** (Jigsaw). When the mod is loaded and **`floatingIslandsTakesapillageControlledOutpost`** is **true** (default), the outpost branch places **`takesapillage:bastille`** or **`pillager_camp`** (weights **1**:**2**) using **`Structure#findValidGenerationPoint`**, with fallback to the vanilla outpost if mod placement fails. - **Biomes O' Plenty on floating islands (TerraBlender):** Configured **`islandBiomeModWeightedEntries`** were skipped whenever **`BiomeSource.possibleBiomes()`** omitted mod ids (common with TerraBlender). Startup diagnostics list ids that **resolve in the registry** rather than only those listed on the biome source.
- **Woodland mansion / igloo on floating islands:** Island biome rolls never included **dark forest**, so **minecraft:mansion** could not spawn; **snowy taiga** improves **minecraft:igloo** odds alongside snowy plains. New config **`islandBiomeWeightDarkForest`** / **`islandBiomeWeightSnowyTaiga`**. **minecraft:mansion** and **minecraft:igloo** are excluded from “strip blocks above procedural surface” like villages so multi-floor builds are not hollowed out. **Note:** **minecraft:fortress** is a **Nether** structure — **`/locate`** from the overworld will not find it.
- **Slow island chunk generation (masked caves):** post-carve stripping called **`columnContains`** on nearly every block per carving step (~98k ellipsoid tests per chunk × carving phases). Stripping now skips blocks that are not cave air / fluids, handles **void columns** and Y outside **`columnTopY` / `columnBottomY`** without per-Y **`columnContains`**, and only runs the heavy test inside the vertical footprint band. Default **`floatingIslandsMaskedCarverNeighborChunkRadius`** is **5** (was **6**) for fewer neighbor chunks per carve; caves and mineshafts stay enabled.
- **Void fall on new-world join:** Starter islands were sometimes **claimed** while **`teleportToIslandCenter`** returned success without checking footing, or placement left join **momentum** carrying through open sky. Failed placement now **reverts the starter claim** and searches the next region; teleport uses **`findNearestIslandFeet`** fallback, **7×7** chunk loading at the destination, and **`stabilizeAfterIslandTeleport`** (zero velocity + reset fall distance). Void-rescue teleports use the same stabilization and wider chunk load.
- **Mineshafts fragmented under islands:** void-column structure trimming was deleting **minecraft:mineshaft** blocks in open-sky columns, cutting corridors between island masses. **`floatingIslandsTrimStripMineshaftThroughVoid`** (default **false**) preserves through-void mineshaft pieces; surface-overhang trimming is unchanged.
- **`/locate structure` watchdog / kick:** vanilla asks for **100** search rings; each can synchronously generate chunks through STRUCTURE_STARTS (heavy for trial chambers). **`FloatingIslandsChunkGenerator#findNearestMapStructure`** clamps rings with **`floatingIslandsLocateStructureMaxRingRadius`** (default **32**).
- **Worldgen CPU (masked carvers):** **`floatingIslandsMaskedCarverNeighborChunkRadius`** (default **5**, vanilla **8**) shrinks the carved neighborhood versus vanilla's **17×17** neighbor scan.
- **Ruined portal rubble in void:** **`minecraft:ruined_portal`** used vanilla's huge search box so **`floatingIslandsRemoveStructuresWithNoLandContact`** could keep a start when **any** corner touched land while this chunk's fragment sat in open void. **`floatingIslandsRuinedPortalChunkLocalLandAnchor`** (default **true**) requires the BB slice **in this chunk** to have island land under its midpoint; **`floatingIslandsTrimStructureVoidBlocksAfterFeatures`** (default **true**) runs **`trimFloatingStructureBlocks`** again before biome decoration so late-placed portal blocks are cleared from void columns.
- **Controlled settlements in the sky:** `JigsawPlacement` heightmap projection uses `pos.getY() + getFirstFreeHeight(...)` where `getFirstFreeHeight` is already an **absolute** surface Y for `FloatingIslandsChunkGenerator`. Anchoring at procedural **top** double-counted; controlled jigsaw anchors now use **Y = 0** when `projectStartToHeightmap` is present so villages/outposts sit on island terrain.
- **Stronghold / library rooms under islands:** **`floatingIslandsCaveStructureRequireStoneYOverlap`** now also applies to **`minecraft:stronghold`** (picker-excluded); strips fortress starts whose Y-range does not intersect island stone at the BB center — bookshelf/chest rooms were often **stronghold** pieces, not monster rooms.
- **Chunk crash (`Asking for biomes before we have biomes`):** **`applyIslandRegionStructureGating`** moved from **`createStructures`** (STRUCTURE_STARTS — proto-chunk has no biomes yet) to the start of **`applyBiomeDecoration`**, so **`chunk.getNoiseBiome`** is safe and worldgen no longer aborts (disconnect / crash report).
- **Vanilla villages:** settlement trim / void-footprint logic now recognizes **`minecraft:village_plains`** (and siblings **`village_*`**) instead of the nonexistent **`minecraft:village`** id; **`removeStructureStartsWithNoIslandContact`** also skips those so footprint sampling cannot discard valid villages.
